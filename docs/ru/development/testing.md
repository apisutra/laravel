# Разработка и проверки Laravel-пакета <a id="section-1"></a>

Нужны PHP 8.4/8.5, Composer 2, Python 3.9+, Git и расширения curl/intl/mbstring/XML.
Для Laravel задано `^13.12`, что соответствует проверенной нижней границе.
Проверки используют fake HTTP и не требуют БД. Выполняйте из checkout адаптера.
Ниже полный набор проверок, а не обязательная последовательность для каждой правки.
Начинайте с затронутых тестов; при изменении реализации запускайте тесты пакета,
анализ и линтер по готовности. Реальное приложение нужно при изменении подключения
Laravel, конфигурации, discovery или поведения, зависящего от bootstrap. Для текстовых
правок достаточно проверки документации и пробельных ошибок; изменённые PHP-примеры
также требуют анализа и выполнения. Проверки архивов и совместимости зависимостей/PHP
нужны при изменении соответствующих областей, в CI и при подготовке выпуска.
Повторяйте успешные проверки только после относящихся к ним изменений, сбоев или новых
оснований для проверки. Для обычных проверок отдельные файлы отчётов не нужны.

```bash
python3 tests/Support/install.py --core ../php
python3 tests/Support/test-install.py
composer validate --strict
composer dump-autoload --optimize --strict-psr
composer test
composer test:integration
composer lint
composer analyse
composer check-docs
composer analyse-docs
composer check-package
```

Для совместной разработки или до появления совместимого выпуска ядра используйте `--core`:

```bash
python3 tests/Support/install.py --core /absolute/path/to/php
```

Установщик создаёт игнорируемые `composer.local.json` рядом с обоими основными manifest
и выбирает их через переменную окружения Composer `COMPOSER`. Их lock-файлы называются
`composer.local.lock`; основные manifest и lock не меняются. `.test/core` указывает на
выбранные исходники, а Composer подключает их симлинком в vendor. Изменения доступны
сразу. Локальная тестовая версия — 0.1.0; это не публикация и не тег ядра.
При повторном запуске снова указывайте `--core`. Для разрешения изменившихся деклараций
зависимостей используйте `--dependencies latest`; локальные manifest заново собираются
из основных.

Без `--core` установщик использует Packagist для ядра в обоих окружениях, даже если
сохранились локальные файлы или прежний симлинк `.test/core`. Обычный `composer install`
тоже использует основной manifest и не требует checkout ядра. Оба варианта требуют
опубликованного ядра, совместимого с `^0.1 || ^0.2`. Полный установщик дополнительно получает
разрешённую ревизию ядра в `.test/core-source` для документации, примеров и проверок
дистрибутива, направляя `.test/core` туда; runtime-зависимость это не подменяет.
Эти каталоги игнорируются и исключены из архивов. Интеграционное приложение продолжает
использовать path-репозитории для проверяемого адаптера и учебного SDK.

Без lock первый install разрешает зависимости и создаёт выбранный lock-файл.
Оба основных lock фиксируют опубликованное ядро; они обязательны для locked-прогонов CI. Локальные разработка и проверки публикации не требуют.
Локальные manifest и lock исключены из Git и обоих форматов дистрибутива.

## Матрица зависимостей <a id="section-2"></a>

В CI и при подготовке выпуска locked запускается на PHP 8.4 и 8.5, lowest — на 8.4,
latest — на 8.5. Выбранный режим разрешения зависимостей применяется и к пакету, и к
приложению. Для локального воспроизведения нужного сочетания используйте отдельные checkout:

```bash
python3 tests/Support/install.py --dependencies lowest
composer test
composer test:integration
# Свежие совместимые версии:
python3 tests/Support/install.py --dependencies latest
```

Установщик показывает разрешённые версии Laravel. Ограничения безопасности Composer
сохраняются. Качество, документация и дистрибутивы проверяются один раз на locked PHP 8.4.
Без `--core` lowest/latest также разрешают ядро из Packagist. Добавьте `--core ../php`,
чтобы проверить эти режимы зависимостей с локальным ядром.
Отдельный Redis smoke проверяет необязательное подключение через Laravel; полной матрицей
атомарного backend владеет ядро. Эти проверки не доказывают lifecycle Octane или отдельного queue worker.

Lowest-набор содержит старый Symfony Translation с deprecation под PHP 8.4.
Диагностика остаётся видимой в stderr; JSON-проверки используют stdout отдельно.
Обновление совместимых зависимостей убирает предупреждения; глобального подавления нет.

## Дистрибутивы и документация <a id="section-3"></a>

`check-package` сравнивает Git- и Composer-архивы и устанавливает каждый в отдельное
Laravel-приложение без dev-зависимостей. Проверяет discovery, его отключение, явные
providers, SDK overrides и config cache. `--staged` проверяет index; временный
`GIT_INDEX_FILE` позволяет выбрать незакоммиченные изменения без изменения staging пользователя.
Достаточно Git tree, даже до первого коммита.

Документация использует общий проверяющий инструмент выбранного публичного ядра:
локальные ссылки, API-декларации, языковые пары и PHP-сниппеты. PHPStan проверяет
Laravel-часть существующего SDK; standalone-часть проверяет ядро.

## Совместная проверка Records SDK <a id="sdk-example"></a>

При изменении примера, используемого им API адаптера или их руководств проверяйте оба
актуальных checkout до слияния. Из каталога адаптера:

```bash
python3 tests/Support/install.py --core ../php
composer analyse-docs
python3 tests/Support/check-sdk-package.py --root . --core ../php
```

Установочная проверка запускает поставляемый пример без dev-зависимостей в Laravel
с адаптером и без него. Проверяет optional discovery, явную сборку, DI, overrides и
кеш конфигурации. Standalone-установку проверяет ядро. Проверка архивов включает эти
сценарии; после неё отдельно повторять их не нужно. Перед выпуском проверьте итоговые
деревья и актуализируйте ревизию ядра. Обычный CI адаптера использует выбранную ревизию
ядра и не обнаруживает последующие изменения другого репозитория. Совместная проверка
checkout закрывает этот пробел во время разработки.
